# Page Fault
- 프로그램이 실행되는 동안 지금 당장 읽거나 쓰려는 메모리 페이지가 물리 메모리(RAM)에 존재하지 않을 때, CPU가 하드웨어적으로 발생시키는 일종의 경고 신호
- 데이터가 필요해서 읽으려고 주소를 봤는데 RAM에 없어서 보조기억장치(SSD/HDD)에서 가져오라고 신호를 주는 상황

## 1. 발생 원인
- RAM의 크기는 제한적
- 우리는 가상 메모리(virtual memory)를 통해 큰 프로그램을 사용 가능
- OS는 프로그램을 실행할 때 프로그램 전체를 RAM에 다 올리지 않음
- 프로그램을 페이지라는 작은 단위로 쪼개어, 지금 당장 실행에 필요한 부분만 RAM에 올려두고 나머지는 보조기억장치에 놔둠
- Page table : RAM에 올라와 있는 페이지들의 주소 매핑 정보를 기록해둔 곳
- CPU가 page table을 조회했는데,  가상 메모리 주소는 있지만 실제 RAN 주소가 비어있을 때 발생

## 2. 처리 과정

1. CPU가 특정 가상 메모리 주소 접근 시도
2. 페이지 테이블 확인 -> RAM에 없음
3. CPU 작동을 잠시 멈추고 제어권을 운영체제 커널로 넘김
4. OS가 SSD의 스왑 영역에서 해당 데이터 검색
5. 물리 메모리의 빈 공간을 확보(RAM이 꽉 찼을 시 안 쓰는 페이지 하나를 디스크로 쫓아냄)
6. 디스크에서 필요한 데이터를 읽어옴(I/O)
7. Page table update

## 3. Thrashing
- SSD 속도는 RAM 속도보다 매우 느림
- RAM 크기가 극단적으로 작거나 실행 중인 프로그램이 너무 많으면, CPU가 페이지 폴트를 해결하느라 디스크에서 RAM으로 데이터를 올리고 내리는 작업만 반복
- 이를 스래싱 현상이라고 함. 컴퓨가 버벅거리고 심하게 멈추는 주원인
